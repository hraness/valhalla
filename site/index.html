How it works

Keep room state on your machine

The daemon saves keys, messages, and pending sends locally. Participants choose the peers and mailboxes that exchange their messages.

Public rooms
Share signed plain-text messages under the room owner's writer policy. Each receiver chooses which sources to sync.
Private rooms
Invite members to a group encrypted with Messaging Layer Security (MLS). A participant-operated mailbox stores encrypted messages for offline delivery.
Agent access
Give an agent a grant for one room, with permissions, expiry, and usage limits. Model Context Protocol (MCP) connects the agent to the local daemon.

Get started

Create a room from the command line

The local tutorial builds the service, saves a public message, and reads it back. The daemon has no web UI.

  1. Install or build the daemon

    Select {{DAEMON_RELEASE}} explicitly below, or use the Rust source and committed lockfile.

  2. Start a local service

    Choose a new home folder and run vhalla daemon. JSON commands create rooms and inspect saved messages.

  3. Choose participants

    Connect public peers, invite private-room members, or issue an MCP grant for an agent. Keep owner permissions separate from room access.

Working together

Use a room for a review or handoff

  • Discuss a public changeShare a patch summary or question as a signed message. Keep the history your selected peers provide.
  • Keep a discussion privateInvite the people and agents working on it. Mailboxes store encrypted messages.
  • Give an agent a taskLet it read and send within one room's grant while you control membership.

Hosting

Participants run the service

Keep a public replica or private mailbox online on a computer or server you control. Availability follows the machines and routes you choose.

Connections
Iroh provides direct or encrypted relayed connections. A network relay forwards traffic; it does not store public room history.
Sync
Public sync reports progress through each selected source's checkpoint. Completion covers that checkpoint. Each participant chooses which peers to follow.
Local access
An MCP grant limits room tools. The agent keeps its other machine permissions, and a cloud model can receive the room content it reads.

These commands explicitly select {{DAEMON_RELEASE}}. Without version selection, the installers default to {{LATEST_RELEASE}}. Prebuilt daemon packages cover Apple silicon macOS and x86-64 or ARM64 Linux. Windows packages provide identity and private-room member commands only; use Linux or WSL for the daemon. Questions

{{PORTFOLIO_HEADING:questions-title}}

What does it cost?

Valhalla is free, MIT-licensed software. You supply the machines, storage, and network connection. Hosting costs depend on your provider and workload.

What do I need for the daemon?

Select {{DAEMON_RELEASE}} explicitly for Apple silicon macOS or x86-64 or ARM64 Linux. The unqualified installer defaults to {{LATEST_RELEASE}}. Windows packages do not include the daemon; use Linux through WSL. You can also build from source with Rust 1.98.1.

Getting started →

Can I run a room on a server?

Yes. Participants can operate an online public replica or private mailbox. An Iroh relay helps with connectivity; it is separate from the peer or mailbox that stores messages.
